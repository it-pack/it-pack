# ADR-001: Hexagonal Layering and Port Boundaries

- Status: Accepted
- Date: 2026-08-22
- Deciders: CommitIt maintainers

## Context

CommitIt wraps git (`czproject/git-php`) but must remain open to other VCS
backends later without touching the domain or SDK. We need a stable, enforceable
dependency structure so that adapters are interchangeable and the core stays
vendor-neutral.

## Decision

Adopt a hexagonal (ports-and-adapters) architecture with the dependency
direction `SDK → Application → Domain ← Contract ← Adapter`:

- Public behavior is expressed through **ports** in `src/Contract/*`
  (`Repository`, `WorkingTree`, `RepositoryFactory`, `RepositoryObserver`).
- The **git adapter** (`src/Adapter/Git/*`) is one implementation of those ports
  and the only layer permitted to depend on `czproject/git-php`.
- `Domain` holds immutable value objects and pure validators; it depends on
  `Common` and `Contract` only.
- `Application` composes factories and applies the observer decorator; `SDK`
  provides the ergonomic facade.

The boundaries are **enforced by `deptrac.yaml`** as a quality gate. A violation
is corrected by fixing the dependency direction, never by adding skips.

## Consequences

- Positive: a future `hg`/`svn`/`fossil` adapter can be slotted in without
  changing the domain or SDK; the git adapter can be refactored freely behind
  its contracts.
- Positive: architectural drift is caught in CI rather than in review.
- Negative: some operations require translating between contract types and
  `czproject` types inside the adapter (accepted, bounded cost).
